## 工具（本机临时件，需重建）

- `$env:TEMP\step-merge.ps1 -FromRev <A> -ToRev <B> [-DryRun]` —— 三方合并一步上游。
  **关键实现点**：三个输入（ours/base/theirs）必须**统一归一为 LF**——`git merge-file` 逐行比较，
  行尾不一致会让每一行都显得"变了"，整个文件塌成一个巨型冲突块（踩过，见下）。
- `$env:TEMP\triage-conflicts.ps1 -Files <paths>` —— 一行一处冲突的紧凑清单。
- `$env:TEMP\which-patches.ps1 -Files <paths>` —— 列出每个冲突块涉及哪些我方 patch。
- `$env:TEMP\summarize-conflicts.ps1 -File <path>` —— 单文件冲突展开（ours/base/theirs 各取前 N 行）。

## 踩坑记录

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **行尾不一致导致假冲突** | 1.9.5 首跑报「`app.js` 1 处冲突，跨整个文件（11654 行 vs 0）」 | 参考克隆 `git show` 出 CRLF，工作树是 LF；`git merge-file` 逐行比较 → 每行都不同 | 三输入统一 LF 归一再合并；修脚本后复测得真实冲突数 **24** |
| **`git show` 行数不可信** | 一度以为 1.9.4 的提交丢了 800 行（`git show` 报 10854，工作树 11654） | `git show` 走 PowerShell 文本管道会改写行尾、影响行数统计 | 用 `git hash-object` 比 blob id（一致即证明内容相同） |
| **`$Base` 是 PowerShell 自动变量** | 脚本里 `$Base` 传参变成驱动器根 `C`，`git show C:...` 报 `invalid object name 'C'` | `$Base` 被 PowerShell 保留变量遮蔽 | 改名 `$BaseRev` / `$TargetRev` |
