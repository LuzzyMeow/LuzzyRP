## 3 · 方向怎么定的（替代三方向门的可审计过程）

三方向门的目的是**不让实现者替用户收窄选择空间**——所以豁免之后，这条纪律转为
「**把取舍摊开写下来、并把理由挂在内容上**」，落点在计划文档 §4.1，摘要如下：

| 项 | 内容 |
|---|---|
| 方向 | **「纸页清单 + 抽页编辑」**：列表是目录（分组行 + 启停开关），编辑时把这一条**抽出来铺满全屏** |
| 为什么是它 | ① **内容驱动**：这两块数据是「很多条长文本」，界面只需回答「有哪几条/哪条开着」与「这一条写了什么」；② **一致性**：与会话总览页（boards-v5 方向 B）同族，复用同一套行规格与 `PageKit` 组件，不给同一类问题发明第二套长相；③ **反 slop**：零新色相、无渐变、无 emoji、无编造统计 |
| 120% 的那一处 | **正文编辑器**（全屏、字数统计、未保存确认）——其余保持克制（「一个细节做到 120%，其他做到 80%」） |
| form 五问 | 已答，见计划 §4.2（含「视觉母题 = 条目即纸页」） |
