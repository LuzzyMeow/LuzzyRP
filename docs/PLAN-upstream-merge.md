## 工具（本机临时件，需重建）

- `step-merge.ps1 -FromRev <A> -ToRev <B> [-DryRun]` —— 三方合并一步上游。
  **关键实现点（踩过）**：三个输入（ours/base/theirs）必须**统一归一为 LF**，且写盘要用
  `WriteAllLines` 之外的方式或事后归一（Windows 默认 CRLF 与 `.gitattributes` 的 `eol=lf` 冲突）。
- `triage-conflicts.ps1 -Files <paths>` —— 一行一处冲突的紧凑清单。
- `which-patches.ps1 -Files <paths>` —— 列出每个冲突块涉及哪些我方 patch。
- `summarize-conflicts.ps1 -File <p>` —— 单文件冲突展开（ours/base/theirs 各取前 N 行）。
- `resolve-block.ps1` / `take-side.ps1` —— 单块替换 / 提取某一边。
- `rename-nav.ps1 -Files <...> [-DryRun]` —— 机械改名（自动跳过冲突块）。
- **分段编译定位法**（模板语法错专用）：Node 侧把模板分片通过 CDP 注入页面，
  用页面自带的 `Vue.compile` 逐段累积编译定位。

## 踩坑记录（供下次同步参考）

| 坑 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **行尾不一致导致假冲突** | 首跑报「1 处冲突，跨整个文件」 | 参考克隆 `git show` 出 CRLF、工作树是 LF；`git merge-file` 逐行比较 → 每行都不同 | 三输入统一 LF 归一再合并（真实冲突数从「1 处巨型」变为 24 处正常粒度） |
| **`git show` 行数不可信** | 误判提交丢了 800 行 | PowerShell 文本管道会改写行尾 | 用 `git hash-object` 比 blob id |
| **`$Base` 是 PowerShell 自动变量** | 传参变成驱动器根 `C` | 保留变量遮蔽 | 改名 `$BaseRev` / `$TargetRev` |
| **注释插进标签属性中间** | 整页白屏 | 解冲突时未注意插入点在标签内 | 分段编译定位法 + 移出注释 |
| **file:// 下 `cssRules` 不可读** | 门禁扫样式表永远找不到规则 | 外部 CSS 跨源限制抛 SecurityError | 改为实测运行时特征（类名/元素）而非扫样式表 |
