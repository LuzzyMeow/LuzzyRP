## 2 · 本基座抓到的真缺陷（已修）

**用户消息的「删除」绕过确认框**：`ChatPage` 里 AI 消息那一支已改为 `pendingDelete`（弹确认），
但**用户消息那一支仍是直接 `removeMessage`** —— 同一功能两条路径行为不一致，而人工走查很容易漏
（谁会想到「用户气泡的删除」和「AI 气泡的删除」待遇不同）。

- **发现方式**：UI 用例「删除消息先弹确认框」点了第一条消息的 ⋯（种子历史第一条是**用户消息**），
  断言确认框出现 → 失败。取证：点完菜单项后 `roots=1`（弹窗关了但**没有出现新的对话框窗口**）。
- **修复**：用户消息分支同样走 `pendingDelete`；单测/UI 测试均转绿。
- **价值**：这正是不引入 UI 自动化就查不出来的那类缺陷（纯逻辑单测测不到「哪一支忘了接状态」）。

## 3 · 已知缺口（如实登记）

- **真实 SSE 节奏 / 真实端点行为**（重试、截断、usage 真实值）仍需人工 + 真机；
- **冷启动链路**（AssetExtractor → Activity → 首帧）无自动化；
- **转场动画的时间线**（抽屉 420ms 交叉淡化）不在本手册范围（属 `tools/page-handoff-test.cjs` 与设计走查）。
