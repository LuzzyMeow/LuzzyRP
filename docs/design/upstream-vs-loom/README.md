# 上游 RP-Hub 1.9.5 vs Loom v4 对照（批 G 基准）

> 2026-09-17 采集。上游在线 demo（sta1n156.github.io/RP-Hub，1.9.6 Preview 构建的 main 分支）
> 与 LuzzyRP v3.1.0-debug（Loom v4，模拟机 emulator-5554 真窗口 screencap）同位对照。
> **结论先行：不换设计基线。** 上游自基线 1.9.3 后的设计增量只有四点打磨（导航面板/世界书
> 全局设置布局/记忆系统样式/移动端体验），且是纯亮色 Tailwind 风、无暗色模式、无 token 纪律；
> Loom v4 在体系完整度（双主题/对比度门禁/动效令牌）上更高。本对照只做**定向借鉴**。

## 逐点判断（四处增量点）

### ① 导航面板
- **上游**：白玻璃卡浮层，条目**两列网格**、按「常用/在线/高级」分组，图标+文字，选中浅蓝胶囊。信息密度高，分组语义清楚。
- **Loom**：全高织层抽屉，单列大行，无分组标题（对话/角色/世界书/预设/记忆/用量/设置/关于），底部品牌语。
- **判断**：上游「分组小标题」值得借鉴（Loom 抽屉 8 项平铺，功能多后可读性会降）；**两列网格不借鉴**（桌面宽屏产物，移动单列拇指可达性更好）。上游无暗色模式，其玻璃观感不迁移——Loom 织层底 + 抽屉已等长转场自有语言。
- **动作**：Loom 抽屉加分组标签（「对话」/「创作」/「数据」三级），用 LoomSectionLabel；不动行布局。

### ② 世界书全局设置布局
- **上游**：扫描深度 + 最大深度两条滑杆**并排双列**，卡片紧凑；但空库 demo 下 Vue 插值裸露（`{{ worldInfoSettings.scanDepth }}`），实际信息架构是「两滑杆一组」。
- **Loom**（lz-world.png）：两滑杆纵向堆叠在一个卡内，滑杆轨道是点阵织纹风格。
- **判断**：Loom 现状已不差；上游并排在 400dp 宽手机上两列各 ~180dp，滑杆过短反而难操作。**不借鉴布局，借鉴一条语义**：上游把「扫描深度」与「最大深度」的从属关系用「一组」表达，Loom 已同构。**不改。**

### ③ 记忆系统样式
- **上游**（up-memory8.png）：基础模式/增强模式**双模式说明文案块**（每模式一段「它是什么」），增强模式=总结+向量召回混合；「压缩率可视化」（memory-compression 进度条，压缩前后字数对比）。
- **Loom**（lz-memory.png）：作用域卡 + 记忆引擎卡（注入开关/召回条数/阈值）+ 检索测试。无模式说明块，无压缩率可视化。
- **判断**：上游**模式说明的写法**（模式名加粗 + 一句话语义解释 + 用户视角的后果）值得抄进 Loom 记忆引擎卡——我们「词面召回」的如实说明可借用此排版（正文已有说明但埋在卡底）。压缩率可视化**不借鉴**：依赖上游「增强模式逐楼替换」的机制，我们无此语义，做一个没有数据支撑的可视化是 filler。**动作**：批 C 做记忆自动总结时，顺手把引擎卡说明按上游模式说明的排版重构（模式名加粗 + 一句话后果）。

### ④ 移动端体验
- **上游**：100dvh 视口变量 + 键盘 inset 变量（Web 层补丁）。Loom 原生已内建（navigationBarsPadding + imePadding，真机取证过）。**无借鉴点。**

## 定向借鉴执行清单（并入批 C/批 E）

| # | 动作 | 落点 | 批次 |
|---|---|---|---|
| G-1 | 抽屉导航加分组标签（对话/创作/数据） | `LuzzyNavShell.kt` 抽屉项列表 | 批 E |
| G-2 | 记忆引擎卡说明文案按「模式名加粗+一句话后果」重构（与自动总结一起） | `MemoryPages.kt` 引擎卡 | 批 C |

**不借鉴登记**：两列导航网格（桌面产物）；世界书双滑杆并排（窄屏滑杆过短）；压缩率可视化（无对应机制）；上游亮色 Tailwind 观感与字体三态（违反字体锁定与 Loom 色彩纪律）。
