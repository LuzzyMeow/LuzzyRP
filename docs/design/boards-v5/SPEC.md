## 0 · 为什么现在做这一页

P4 把数据层打通了（角色 / 分支 / 消息 / 记忆 / 预设全部落 Room，迁移端到端跑通），
但界面上**看不到「我一共有哪些会话」**：聊天页一次只显示一个角色的一条分支。
P4-C 要求补上**跨角色平铺总览**——数据层已就绪（`ChatSessionRepository.overview()`），缺呈现层。

## 1 · 顾问式重述（Phase 2）

这一页的用户是**同一个人**：一个把角色扮演当成长期写作的人。他可能在两三年里攒下
几十张角色卡、上百条剧情分支。他要的不是「管理」数据——不是统计、不是排序、不是批量操作；
他要的是**重新走进某一段**：想起「那天在书店楼上，雨还没停」，然后点进去继续写。

所以这一页的本质不是列表管理，而是**目录页**（table of contents）：它要让人一眼看见
「我写过什么」，并且能凭**一句话的余温**认出是哪一段，而不是靠文件名或时间戳。
它的高频动作只有一个——**读一眼，认出来，点进去**。这决定了：

- **末条正文预览是主角**，不是配角：它是唯一能让人「想起来」的东西；
- 角色名与分支名是**层级**（谁的哪条线），不是标签；
- 数字（几楼/几条）只需要存在，不需要强调——它不是仪表盘；
- 空会话（有分支但还没聊过）**必须看得见**：用户会用它想起「我本来想开这条线」。

情感基调：**安静、克制、有书卷气**。与既有的「织机 Loom」一致：暖纸底、Lora 做名牌与标题、
PuHuiTi 做正文、珊瑚陶土色**稀缺**使用（`craft/color.md`：单屏 ≤2 处 accent）。

**基于这个理解，我直接做 3 个不同方向的真实版本给你看**（见本目录三份 HTML + PNG）。

## 2 · 设计 spec（Phase 3，三方向的唯一共同输入）

### 2.1 产出形态与尺寸（必填）

- **形态**：Android 手机页面（Compose 应用内的一个新页面），**390 × 844 dp**；
  截图按 **2× ** 渲染（780 × 1688 px），因为要在桌面看细节。
- **页面 chrome 固定**（三方向一致，这是品牌常量不是设计变量）：
  顶部 64dp 透明 `TopAppBar`（汉堡 + 页标题「会话」，与既有七页同构）+ 24dp 状态栏。
  内容区从 y=88dp 起，底部无 bar（本页不是聊天页，没有输入岛）。

### 2.2 内容（**真实数据，不是编排的假数据**）

数据来自模拟器上**真实迁移进来**的旧数据（`docs/DESIGN-migration.md` §11.3），
共 6 条会话 / 5 个角色：

| 角色 | 分支 | 条数 | 末条正文（截断） |
|---|---|---|---|
| Vanio | 主线 | 5 | 靠窗那张椅子是藤的，坐下去咯吱一声… |
| Vanio | 留在书店 | 5 | &lt;thinking&gt; [情景意图分析] 林澈明确做了两件事… |
| 谢昭 | 主线 | 1 | （会议室里只剩下两个人。）「方案我看过了。」… |
| 夏梧 | 主线 | **0** | （空） |
| 旧档角色 | 主线 | **0** | （空） |
| 仅旧库角色 | 主线 | 2 | 你在哪一年？ |

**两条真实数据带来的约束（这正是用真数据的价值）**：

1. **长预览与脏前缀**：Vanio 分支的末条以 `<thinking>` 开头——那是**真实缺陷**
   （模型的思维链泄漏进了正文，与 `{{char}}` 未替换同属 P5 待修项）。
   设计上按「**原样展示用户数据**」处理，不美化、不隐藏；三条方向都要能容纳
   任意长度、任意脏内容的预览。
2. **空会话必须可见**：两条 0 条会话的存在本身就是信息。不能过滤、不能折叠、不能显示成灰条。

### 2.3 品牌约束（**不可协商**）

- **色板**：只用 `DESIGN-compose §2` 的 M3 令牌（HCT/TONAL_SPOT，seed `#CC785C`）。
  亮：surface `#FFF4F1` / surfaceContainer `#FCEAE5` / outline `#85736E` / primary `#8F4C35` /
  tertiary `#6A5E2F`；暗：surface `#231917` / surfaceContainer `#271D1B` / outline `#A08D87` /
  primary `#FFB59D`。文字色取 neutral T10/T90（= `#231917` / `#F1DFDA`，与表内
  「暗画布」同值，是同一构造步骤的产物，非临时发明）。
- **字体锁定（硬性规定 4）**：Lora（display/名牌/标题）+ AlibabaPuHuiTi 3（正文），
  均为仓库内本地 TTF，HTML 里 `@font-face` 直接引用 `fonts/*.ttf`。
- **禁**（`craft/anti-ai-slop.md` 七宗罪）：emoji 作图标、紫/靛默认 accent、双色 trust 渐变、
  圆角卡+左彩色竖条、编造数字（「10× 更快」）、占位文案（lorem / feature one）、
  Inter/Roboto 做 display。
- **accent 纪律**（`craft/color.md`）：单屏 `--accent`（primary）可见使用 ≤2 处。
- **触控基线**（ui-ux-pro-max 优先级 2）：可点行高 ≥44dp，间距 ≥8dp。
- **对比度**（priority 1）：正文 ≥4.5:1，大字/元信息 ≥3:1。
- **动效**：本页为静态稿，只有页面进入（壳层已有 200ms ease-out / 退出 140ms，`open-design` 令牌）。
  三方向都不新增动效。

### 2.4 三方向的取法（Phase 4，串行 + 物理隔离）

本轮为单 Agent（无 subagent 能力）→ 按 `huashu-design` 的「不支持 spawn 的 runtime」规则
**串行跑三套逻辑**，每套只看本 spec、不看另两版，并用三个不同 anchor 隔离趋同：

| 方向 | 逻辑 | anchor | 结构差异（骨架级，不只换色） |
|---|---|---|---|
| **A** | 逻辑一 · 秒数轮盘 | `date +%S` = 42 → 42 % 20 + 1 = **3** → 网页库 #3 **孟菲斯复古拼贴最大化**（还原度 72%，须标注降级部分） | **不等尺寸模块 + 错位拼贴**：非均匀网格、块大小不一、刻意不对称张力 |
| **B** | 逻辑二 · 现实参照 | **Things 3**（Cultured Code）的分组列表：粘性组头 + 统一行高 + 右侧元数据对齐 | **统一行高 + 粘性组头 + 右对齐元数据**：信息效率优先，无卡片感 |
| **C** | 逻辑三 · 最佳设计师 | **iA Writer 的 Library**（Information Architects）：排版即界面，零容器 | **纯文本目录**：无卡片、无 chip、无分隔线，只靠字号/缩进/留白分层 |

**关于轮盘方向的语境内诠释**：本项目的 `DESIGN.md` 是品牌契约（`open-design`：所有 UI 改动必须遵循），
品牌令牌与字体**不参与三方向选择**（`huashu-design`：风格词收窄解释空间，不转移选择权；
此处相反——品牌固定，风格变化只能落在**结构与构图**上）。因此方向 A 取孟菲斯的
**构图基因**（反网格、错落、不对称），色彩与字体仍严格走品牌令牌。
**降级声明**：孟菲斯的「做旧纸质肌理」无法用纯 CSS 还原（原风格库自述还原度 72%），
本方向**不假装做出该质感**，只用色块与错位表达其构图精神。

### 2.5 视觉母题（form 第五问的答案）

**「书脊与页码」**：这一页的每一行都是某一本书的一个断面——角色是书脊（竖排的一列），
分支是章节，条数是页码。母题来自内容本身（多年的长篇写作），不是从风格标签抽签：
三方向分别用「拼贴的书页」「目录的条目」「卷首的章次」三种方式表达同一个母题。

### 2.6 图片策略（Phase 3.5 checkpoint）

**本页图片非内容必需**：角色的头像在真实数据里本来就是**可缺**的（迁移数据里三张卡有头像、
两张没有），而唯一必然可画的「图」是**首字字母**。
因此三方向**都不使用照片或生成图**，头像位一律走「有图显示图、无图显示首字 monogram」的
真实降级路径——这是诚实 placeholder，不是色块糊弄。**不调用生图。**

## 3 · 三方向速览

| | A · 错落拼贴 | B · 分组行 | C · 目录页 |
|---|---|---|---|
| 骨架 | 不等尺寸卡片 + 错位 | 粘性组头 + 等高行 | 单一文本列 + 缩进层级 |
| 预览位置 | 卡内 2 行 | 行内 1 行（省略） | 独立小段，2 行 |
| 数字表达 | tertiary 色块（楼数） | 右侧对齐裸数字 | 括号里的细体数字 |
| 空会话 | 空卡（占位感明显） | 灰字「还没开始」 | 「（空）」+ 缩进仍保留 |
| avatar | 圆形 monogram（叠在卡角） | 行首 36dp 圆 | **无 avatar**（排版优先） |
| 与品牌的关系 | 张力最强，需盯 accent 数量 | 最保守，最像现有七页 | 最有作者感，最不像「列表」 |

**共同点**（保证可比）：同一套令牌、同一套字体、同一份真实数据、同一个页面 chrome、同一尺寸。
