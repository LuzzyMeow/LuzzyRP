    2.聊天页
    2.1 聊天页的agent输出时的思考卡片出现重大bug，目前的 CoT 思考链实现有严重问题，需要彻底重构。请按以下 3 个核心要求修改代码，具体看后3点内容
    2.2 结构分层与去重（解决重复显示）：
    请将“思考过程”严格封装在独立的 Thinking 组件内，绝对不要把思考链的内容塞进最终的模型对话消息（content）里。
    · 正确逻辑：前端维护一份独立的 thinkingSteps: [] 状态。
    · 错误逻辑：思考内容作为 Markdown 的一部分直接输出在消息气泡里（这会导致重复打印，因为最终回答也会在下方展示）。
    2.3 节点与连线 UI（解决没有节点）：
    使用类似 Ant Design 的 Timeline (时间轴) 或 Steps (步骤条) 组件重构 UI。
    · 外层：一个顶部的“Thinking”折叠面板，默认可收起（手风琴样式）。
    · 内层：自上而下的垂直流线。每个步骤是一个节点，左侧带有状态圆圈（空心=待执行，动态加载中=执行，绿色对勾=完成）。右侧紧跟步骤名称和简要说明。
    · 交互：支持点击展开单个节点看详情（如：原生思考 108字 -> 点击展开具体思考文本）。
    2.4 流式渐进渲染（解决瞬间全崩）：
    必须结合后端思维流的 SSE（流式接口）来实现渐进式更新。
    · 不要等思考全部完成再渲染。当第一个思考步骤的 token 开始返回时，UI 立刻渲染出第一步的“节点标题”。
    · 文字随时间显示：在“原生思考”节点里，思考文字要像打字机一样逐字渲染，而不是等到思考完成才把整段文字塞进来。
    2.5 当前折叠收起状态的 UI，外框和图标结构保持现状不变，仅修改内部排版逻辑：排版方向改为横向，将内部容器里的文字和图标布局，从纵向或竖排文本改为横向弹性布局，并做好防截断与溢出处理、空间保证
